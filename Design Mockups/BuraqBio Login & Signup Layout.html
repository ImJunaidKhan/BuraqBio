Builder notes: rebuilding auth.html by hand

One file, auth.html, holds both states. The toggle at the top of the card just shows one form and hides the other — no page reload, no second file. The login form above opens with its error state already visible so you can copy the error styles directly. Gold appears on the wing, the focus rings and the “Bio” in the wordmark; red appears only on errors.

1 · Layout map — build it in this order

Each row is one block of auth.html, top to bottom, with the tag and class names used on this page. Reuse the global .glass, .btn-primary and .input from your style.css — the only new CSS this page needs is listed in step 3.

1
Dark page<body class="dark">

Deep Start background plus two or three soft purple glow divs (blurred radial gradients, position absolute) behind everything. The section is flex, centered both ways, min-height 100vh.

2
The card.auth-card.glass

One card, width min(440px, 100%), padding 36px. Glass recipe from the guide: fill white 13%, border white 35%, blur 18px saturate 160%, radius 20px.

3
Stacked logo.logo-stack

Golden wing image centered (86px), wordmark under it: Buraq in white bold, Bio in gold. One tagline line in white 62%.

4
Toggle.toggle

A flex pill with two buttons. The active one gets the Metro Purple background. One small JS function switches which form is visible and which button is active.

5
Login form#formLogin

H1 “Welcome back”, sub-line, error banner, email field, password field (with the field-level error text under it), full-width Log in button, right-aligned Forgot password link, then the switch line with a top border.

6
Signup form#formSignup

H1 “Create your page”, email, password with a hint, then the username claim group: a flex box that looks like one input, with the buraqbio.link/ prefix as a span inside it. Feedback line under it changes live as you type.

7
Switch lines.switch-line

Each form ends with the line that jumps to the other state (“New to BuraqBio? Create your page” / “Already have an account? Log in”). Same switchMode() function as the toggle.

2 · The three username states

The feedback line under the username field is always in one of these states. In your real build the “taken” check reads the usernames node in Firebase; here a small demo list stands in so you can see all three.

✓
buraqbio.link/yourname is available
Green text, green ring on the field. Create button can go ahead.
✕
buraqbio.link/ali is already taken
Red text, red ring on the field. Block signup until it changes.
✕
Invalid — 3 to 24 chars, lowercase letters, numbers and _ only
Same red styling. One regex does this check: /^[a-z0-9_]{3,24}$/

auth.js — toggle + username checker
// Toggle: show one form, hide the other
function switchMode(mode){
  formLogin.classList.toggle("hidden", mode !== "login");
  formSignup.classList.toggle("hidden", mode !== "signup");
  tabLogin.classList.toggle("active", mode === "login");
  tabSignup.classList.toggle("active", mode === "signup");
}

// Username checker: runs on every keystroke (input event)
var taken = ["ali","admin","support","buraqbio"]; // demo list — real build reads Firebase
usernameInput.addEventListener("input", function(){
  var v = usernameInput.value.trim().toLowerCase();
  if(!v){ setState("", "3 to 24 characters — lowercase, numbers, _ only."); }
  else if(!/^[a-z0-9_]{3,24}$/.test(v)){ setState("err", "Invalid — 3 to 24 chars, lowercase letters, numbers and _ only."); }
  else if(taken.includes(v)){ setState("err", "buraqbio.link/" + v + " is already taken."); }
  else { setState("ok", "buraqbio.link/" + v + " is available."); }
});
